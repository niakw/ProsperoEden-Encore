# R23 — #71 SDL rumble and #143 Qt/SDL mouse drift: native frontend boundary

**11 November 2026.** Read-only source decisions at frozen Encore audit vendor `22b69d6053db41b74edac2633c012f925b84f69e`. Both upstream commits alter desktop/SDL input behavior; neither is copied to PS5. This is an E1 **native frontend selection** disposition, NOT an all-build source-exclusion or tested console behavior claim.

| Upstream | Actual changed source and behavior | Pinned Encore source | PS5 current-native decision |
|---|---|---|---|
| **#71**, `fb51a1253` | SDL driver's own 250 ms vibration worker/queue removed; SDL joystick `SetVibration` now invokes `joystick->RumblePlay` directly. | `vendor/sources/eden/src/input_common/drivers/sdl_driver.cpp` blob `91589063b50548f3142ffdc36dbad2b090238fc5` still owns the old SDL queue. | The actual PS5 gamepad route is `headless/pad.cpp` blob `b6fa427d84f6c8af25a35f4787923d79ab891d67`: `PadEngine::SetVibration` / `Pad::TakeRumble` consumed by `scePadSetVibration`. No `SDLDriver::SetVibration` is used in this *native pad rumble path*. **Do not transplant the desktop SDL thread rewrite into the Sony native pad flow**. |
| **#143**, `d9159fefd` | Changes `Mouse::UpdateMotionInput` and `UpdateStickInput` signatures and notification timestamps, *and* adds periodic mouse notifications to desktop Qt `src/yuzu/bootmanager.*` and SDL `src/yuzu_cmd/emu_window/emu_window_sdl3.*`. | `vendor/sources/eden/src/input_common/drivers/mouse.cpp` blob `4444f0ac3b34ab36bb651f25088dc35e03c79de3` still owns the original mouse notifier. | The reviewed native `headless/main.cpp` and `headless/pad.cpp` do not implement the Qt/SDL mouse timer or invoke `GetMouse()->NotifyChanged`; PS5 controllers are processed by `PadEngine`. Porting only the shared mouse class **without its UI timer owner** would be incomplete. Native mouse/SDL input support is not demonstrated, so **no present native-port change**. |

**Important caveat:** the pinned `src/input_common/CMakeLists.txt` may compile `drivers/mouse.cpp` and SDL driver source into an input library on non-Android platforms. These decisions concern **guest-visible execution ownership of the PS5 native frontend**, not a claim that the objects cannot appear in a build. A linked-ELF usage analysis and actual PS5 input test would be necessary to certify unreachable code. Reopen both if a PS5 mouse or SDL controller frontend is wired, or if a native rumble issue is reproduced.

**Outcome:** two source-semantic decisions, zero integrated fixes and zero new PS5 runtime proof. They must not be used as blanket evidence that SDL- or mouse-related code is safe on other host platforms.
