## #154 — Firmware 23 HLE is a multi-service source gap, not only NS cmd23

Upstream [`e7a96c7907fb`](https://github.com/eden-emulator/mirror/commit/e7a96c7907fb) touches **13 files**: advances HOS API 22.5→23.0 and digest policy, adds SVC `GetInfo` IDs 37/38, AM `SelfController` IPC command 240, AM creator version range fixes, `fsp-srv` IPC 2 (`OpenDataFileSystemByCurrentProcess`) and alias 210 (`SetCurrentProcess`), and PCTL IPC 1460 + exact 0x18 response from 1459. These are guest command/ABI changes, not mere branding.

Pinned current vendor original `sources/eden/src/core/hle/api_version.h`, blob **`29b4f4008ce49205b3453809b8ce77193435f512`**, still reports `HOS_VERSION_MAJOR=22`, minor 5. `sources/eden/src/core/hle/service/filesystem/fsp/fsp_srv.cpp`, blob **`fdbd50ed7a2192cf04af80b398d4ecdc82bd6b7e`**, still registers command 2 with **null handler** and lacks the new command 210 entry. The original `svc_info.cpp`, blob **`e6190ac33a46cb13289128db27a5e92e728907d6`**, has no `Unknown37`/38 result stub. `application_creator.cpp`, blob **`e3bb92c3a41aa2e9ee92d6a26ec433e7d24e0410`**, passes fixed max 22, `library_applet_creator.cpp` blob **`c20a77f8c40c7fbf023411fd47a299662b798cb3`** limits guest applets to firmware 14..22. PCTL `parental_control_service.cpp` blob **`97c178799e264eb9b798351cf0f4846db8f6b09d`** misses 1460 and 1459 explicit 0x18 typed struct.

Most importantly, PS5 native CMake **replaces** original `self_controller.cpp` with maintained `vendor/encore-active/ns2-runtime/self_controller/core/hle/service/am/service/self_controller.cpp`, blob **`ad2b043f972170651b61d2d33aea4082e95c47cf`**, and this selected owner also lacks `Unknown240`; DO NOT blindly patch the original unused source. The draft isolated [#54](https://github.com/niakw/ProsperoEden-Encore/pull/54) is about **NS service command 23** (a distinct separate work item) and is not proof that these upstream FW23 service commands are covered on current `main`.

**Verdict:** E1 **verified multifile native HLE/IPC source gap**, not implemented. Qualify expected request/response sizes and handles per guest firmware, case 1459 exact 0x18 payload, command 210 routing, AM overlays/launchers and commands 37/38; do not misrepresent stub return-success as real system semantics. Test old firmware 19/22 and FW23 titles, extracted ROMFS and save data, self controller events, and **console title boot**. Coordinate with isolated PR #54 but do not merge/rebase it from audit branch.

## #97 — overlay layer policy and SGSR applet branch absent in active PS5 presentation

Upstream [`99bf8cf51afb`](https://github.com/eden-emulator/mirror/commit/99bf8cf51afb) changes three files: `am/window_system.cpp` changes `z_index=Overlay` to conditional `IsOverlayOpenLocked(*applet) ? Overlay : Background` for overlay applets; `hid_core/resources/npad/npad.cpp` moves controller callback registration from activation into `NPad` constructor; and Vulkan `present/layer.cpp` avoids passing applet image through SGSR, whose effect can black out applet composition.

Current original `sources/eden/src/core/hle/service/am/window_system.cpp`, blob **`38587914307682fd31d9fcd4ca3b98cf6cb8ffc9`**, still assigns `z_index = Overlay` unconditionally when `is_overlay`. PS5 native CMake selects maintained `vendor/encore-active/eden-core/src/hid_core/resources/npad/npad.cpp`, blob **`4ac313c1618ca1a163393997e5d26dc1f69cb814`**, not original NPad `e7a1ee2bf364ca8ac2127730b5d3801ecefb758e`; **the maintained callback is still registered in `NPad::Activate(u64 aruid)`, not constructor**. This is a lifecycle difference, not proven to cause user-level controller loss without tracing callback delete/re-register and applet ARUID transitions.

PS5 native `headless/vulkan.cmake` selects the Encore-owned `headless/vulkan_present_layer_r24.cpp` blob **`dea657ef3911828b9437aced16ec9863aeb3b30a`**, *not* original `present/layer.cpp` blob **`14935f92bb450973e85237fed52f8dea6d172688`**. Maintained layer **always invokes `sgsr->Draw` when SGSR chosen**; it currently has no `is_applet`/recording-stack predicate that would skip SGSR on applet content. These are the true three owner surfaces to review (AM original, NPad maintained, layer maintained), not an import of the inactive original render layer.

**Verdict:** E1 **verified relevant applet overlay/SGSR/HID source gap**. Actual user-observed applet darkness/black screen is plausible but not demonstrated from file comparison alone. Full acceptance: applet overlay open/closed foreground z-order; SGSR bypass only on correct applet layer masks, not game content; NPad aruid callback registration and teardown with multiple controllers; graphics filter on/off and AA/upscaler/FG combinations; real PS5 applet transitions. Do not change the renderer graph or duplicate a processing stage without proving that these paths are current.
