# NVIDIA Maxwell / Ampere GPU reference register — 2026-11-19

> Scope: Encore's *guest* Maxwell (NS1) and Ampere (NS2) GPU semantics translated to *host* AMD RDNA2 / Vulkan RADV on PS5 13.60. An NVIDIA CUDA compute performance number is not a valid PS5 tuning constant. All entries below identify original evidence and explicitly separate it from our inferences.

## Reviewed paper details: useful for correctness versus performance

**Maxwell paper (Mei/Chu).** Its Table 3 (p. 4) compares GTX980 Maxwell with GTX780 Kepler and GTX560Ti Fermi; Table 5 (p. 8) summarizes *measured* cache structures. The GTX980 unified texture/read-only L1 cache of 24 KiB and 32-byte lines is a desktop measurement, **not** an Encore allocation parameter. The fine-grained P-chase methodology (pp. 5–6) adds data dependence so the second clock read cannot overtake the memory access. Figure 14 (p. 10) shows that TLB and cold-cache behavior can dominate latency on the measured desktop Maxwell, without proving any corresponding PS5 JIT, GMMU or Vulkan bottleneck. Figure 12 and Table 6 (p. 9) show that bandwidth depends on occupancy and instruction-level parallelism, not just memory-bus peak. Table 8 (p. 12) gives GTX980 2/4/8/16/32-way shared bank-conflict latencies of 30/34/42/58/90 cycles; this is a *physical GTX980* benchmark rather than a correctness contract for the emulated guest shared-memory bank.

**Ampere paper (Abdelkhalik et al.).** Fig. 4 (p. 4) demonstrates how 32-bit clock reads can introduce an unexpected `DEPBAR` in generated SASS; source PTX and dynamic SASS must be compared. Table II (p. 5) distinguishes dependent and independent arithmetic latencies. Table III (p. 6) details the SASS tensor forms `HMMA`, `IMMA`, `DMMA` and `MOVM` layout use, and Table IV reports A100 global/L2/L1/shared ld/st latencies of 290/200/33/23/19 cycles respectively. These figures help explain producer/consumer and lane semantics but **cannot** justify hardcoding host delays, bypassing guest fences or assuming A100-only datapath features in T239.

## Acceptance and investigation order

1. **Before a native build:** verify exact engine main / vendor gitlink, six-source-suite preflight, core fast gate, vendor host checks, native CMake/source graph, security and outstanding compiler warnings. Documentation-only updates never count as a native binary.
2. **Before attributing NS2 startup crashes to shaders:** confirm a captured guest graphics/compute program, opcode words, stage, guest PC and per-title GPU/session lifetime. The recurring `PC=0x4` requires a separate P0 guest fault diagnosis.
3. **Before an opcode or barrier fix:** compare reviewed lowerers in [EglantinePS5](https://github.com/heydemoura/EglantinePS5/blob/main/Eglantine/src/shader_recompiler/frontend/ampere/lower_to_maxwell.h), [Lichii](https://github.com/zortos293/Lichii), [Eglantine](https://github.com/Eglantine-Community/Eglantine) and relevant Mesa/NAK `sm70` ISA field mapping; preserve source version, permissions/licences and fail-closed unsupported modes.
4. **For FC27:** reproduce one cold match, one warmed match, exit/relaunch and detailed-logging toggles; correlate per-frame FPS/HUD delay with shader-compile counters, CPU/GPU wait and persisted driver blob. Keep observed console improvement independent of source-only tests.
5. **For MKW/Bananza:** only after guest execution reaches real shader/program submission, compare negative-cache rejection histograms, GMMU backing, texture/ASTC state, compute barriers, 3D and VI2 present. Guest progress is not an automatically successful GPU frame.
6. **Final PS5 status:** distinguish host compile, native SELF, valid artifacts, installed app, launched guest, valid rendered frame and gameplay. A green build alone closes none of the console P0/P1 issues.
